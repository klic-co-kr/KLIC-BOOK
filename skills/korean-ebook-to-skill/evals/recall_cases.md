# 회상 평가 (recall) — 부록C 사례 단위

> 목적: 후보(candidates)가 부록C **제1부** 사례를 얼마나 빠짐없이 아우르는가.
> 회상은 **사례 단위**(chapter-bucket이 아닌 case 단위)로 잰다.

## 기대

- 부록C 제1부 전체 사례 색인: **약 112건**(책 전체 기준).
- 본 파이프라인 테스트 fixture는 이 중 일부 샘플(6건)만 포함 — 전체 책 기준
  회상은 실서적(E2E, Task 10)에서, 여기서는 **사례 단위** 매칭 로직의
  정합성만 검증한다.

## 매칭 규칙 (case 단위)

- 부록C 파싱(`appendix_c.py::parse_cases`)은 사례를 **장별 로컬 순번**
  case_id(`"N장-M"`)로 파싱한다. 전체 제1부 연속 번호(idx)가 아니라 장별
  리셋되는 로컬 인덱스를 쓴다 — candidate의 `appendix_c_refs` 관례와 일치.
- 후보의 `appendix_c_refs`(예: `"2장-1"`)를 파싱/분해하지 않고 **case_id 집합과
  그대로 교집합** 매칭한다.
  - v1 버그 원인: ref를 `split(" ")`/파싱해 장 버킷으로 매칭 → 회상률 항상 0.
  - 수정: 집합 교집합만(`compute_recall`).

## 회상률 산출

```
recall = |후보 refs ∩ 전체 case_id| / |전체 case_id|
```

covered / uncovered 리스트를 함께 반환(`RecallResult`).

## 비고

- 제2부(자료 출처)의 `"서문 / 1장"` 헤더는 사례가 아니므로 파싱에서 제외된다.
- 범위 헤더(`4~5장`)는 첫 장(4장)으로 귀속.
- 본 문서는 사례-단위 회상의 **기대와 절차**를 규정한다. 통과 임계는 spec §9에서
  별도 정의(전책 기준 회상 ≥ 목표치).

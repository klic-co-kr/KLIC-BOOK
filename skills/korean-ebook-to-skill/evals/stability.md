# 안정성 평가 (stability) — Jaccard 3×2 절차

> 목적: 파이프라인(특히 ANTHOLOGY 서브청크 + candidates 승인)이 실행마다 얼마나
> 안정적인지 잰다. 비결정적 단계(임계 char 기반 서브청크 등)의 드리프트를 잡는다.

## 절차 (3×2)

동일 입력 책에 대해 파이프라인을 **3회** 실행하고, 각 실행의 산출(세그먼트/후보
아이디 집합)을 **2개 레이어**에서 비교한다.

- **레이어 1 — 세그먼트 집합** (`extract.py` 결과 chunk id 들)
- **레이어 2 — 승인 후보 집합** (`candidates.yaml`의 `id` 들)

각 (실행 i, 실행 j) 쌍에 대해 **Jaccard 유사도**를 구한다.

```
Jaccard(A, B) = |A ∩ B| / |A ∪ B|
```

3회 실행 → 3쌍(1-2, 1-3, 2-3) → 쌍당 레이어 2개 → 6개 Jaccard 값.

## 게이트 임계

**평균 Jaccard < 0.5 → 게이트 강제 (gate 강제).**

게이트 강제 시: 파이프라인을 안정화(임계값/시드 고정 등)하기 전까지 승인 불가.
`approval_log`에 stability-blocked 사유를 기록한다.

## 통과 기준

- 레이어 1(세그먼트) 평균 Jaccard ≥ 0.5
- 레이어 2(후보) 평균 Jaccard ≥ 0.5

두 레이어 모두 임계 충족 시 stability PASS.

## 비고

- ANTHOLOGY 서브청크는 `ch8` 케이스별 분할이므로 레이어 1이 특히 민감하다.
- 서브청크 임계 char 값이 바뀌면 레이어 1 Jaccard가 크게 요동친다 → 게이트가 잡는다.

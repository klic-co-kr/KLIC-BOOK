# skill-utility 평가 (v1 정성, MUSE evaluation 차원)

> 목적: 생성된 스킬(SKILL.md) **자체의 유용성**을 잰다. 지식 원문에 충실하면서도
> 독자의 질문에 실행가능한 답을 주는가. v1은 수동 채점(정성 루브릭)이다.

## 평가 설계 (held-out)

ch2 사례(PSF 3관문 · POC 연옥)는 **hold out** — 생성 단계에서 직접 다루지 않은
질문을 스킬에 던져, 원문에 충실한 답이 나오는지 잰다. 생성 SKILL.md에 질문 →
채점(수동). v1은 자동 채점하지 않는다.

## held-out 질문 (ch2 케이스 제외)

1. **"PSF 3관문 검증 어떻게?"**
   기대: 3관문(통점 · 경제성 · 실행가능성) 명시 + 근거 `ch02§2.2` + 부록C 사례.
2. **"AI POC가 왜 연옥에 빠지나?"**
   기대: MIT 5대 사망원인(기술 자체가 아님) 명시 + 근거 `ch02§2.1`.
3. **"TTV 임계 기준?"**
   기대: 주 단위(2~6주) 임계 + 부록A 지표 참조.

## 평가 루브릭 (1~5점)

| 항목 | 의미 | 5점 기준 |
|------|------|----------|
| 충실성 | 원문 §/사례와 일치 | 인용 §가 정확히 일치 |
| 근거체인 | 부록C/§ 근거 제시 | 출처 § + 사례 번호까지 제시 |
| 실행가능성 | 독자가 다음 행동을 취할 수 있는가 | 구체 절차/체크리스트 제공 |

**통과 기준:** 세 항목 모두 ≥ 3 → pass. 어느 한 항목이라도 < 3 → fail(원문 회귀).

## 절차

1. ch2 케이스 hold out (생성 입력에서 배제).
2. 생성된 SKILL.md에 위 held-out 질문을 던진다.
3. 위 루브릭으로 수동 채점 (v1).
4. fail 항목은 원문 회귀 후보로 회수 → candidates.yaml에 추가 (승인 게이트).

## 비고

- v1 Self-Review가 "skill_utility.md 존재"라고 거짓 명시했던 항목. 이 파일이 그
  부채를 상환한다.
- 자동 채정(LLM-judge)은 spec §9 v2에서 검토. v1은 수동.

# 한글 문체 지침 — 집필·번역 전 준수 (korean-style)

원천: [fluent-korean](https://github.com/snflkd/fluent-korean) (Claude Code output-style,
국문과 전공 저자), [polish-doc](https://github.com/albertrim/polish-doc) (문체 텔·축약
원칙 — 2026-09 채택). 이 문서는 KLIC-BOOK 원고 작성 에이전트·번역 작업에 맞게 채택한 버전.
**챕터 집필·번역 프롬프트에 이 문서 경로를 넣고 시작한다.** 빌드 QC의 G4 게이트가
같은 규칙을 기계 검사한다(`scripts/korean_lint.py`).

목표는 수려한 문체가 아니라 **의미가 손실되지 않는 명확한 한국어**다.

## 문장 단위

1. **의미 있는 문장 성분을 생략하지 않는다.** 토큰을 아끼려다 조사와 목적어를
   뭉개면 독자가 맥락을 추측하게 만든다.
   - 나쁨: "그러면 경고가 붙습니다."
   - 좋음: "그러면 이미 작업 중인 파일에도 경고 표시가 추가됩니다."
2. **완결된 문장으로 끝낸다.** 명사구·부사구·연결어미로 문장을 끊지 않고
   서술어와 종결어미로 맺는다. (헤딩·목록 항목은 예외 — 명사구 종결 허용)
   - 나쁨: "이 결정은 이후 중요 정책이 갈리는 자리. 컨텍스트 압축 전 신중 반영한다."
   - 좋음: "이 결정은 이후 중요한 정책에 지속적으로 영향을 주기 때문에,
     컨텍스트가 압축되기 전에 신중히 반영합니다."

## 구 단위

3. **조사와 어미를 생략하지 않는다.** 부사·보조사·선어말어미·보조 용언을
   적극적으로 써서 관계를 명시한다.
4. **한자어 + 조사·어미 조합을 활용한다.** 구체적 한자어에 조사를 붙여 어휘
   사이의 관계를 확실히 한다. 명사만 나열하면 관계가 사라진다.
5. **비유적 어휘로 일반 명사·동사를 대체하지 않는다.** 일상 문어·해당 분야에
   관용으로 정착한 표현은 그대로 쓴다.
   - 나쁨: "코드로 박는 자리" → 좋음: "코드에 명시하는 상황"
6. **엠대시(—)를 자제한다.** 앞뒤 관계를 지나치게 함축한다. 콜론이나 접속사로
   푼다. (G4: 1000자당 6개 초과 시 경고)

## 용어

7. **고유명사·기술용어**는 정착된 번역어·음차 우선, 없으면 원어 유지.
   독자가 이해하기 쉬운 쪽을 택한다.
8. **사용자·원문의 어조를 모방하지 않고** 이 지침을 일관되게 유지한다.

## 문체 텔 (polish-doc)

9. **문장 길이에 천장이 있다.** 한국어 문장은 평균 40자 안팎, 상한 2줄(약 80자).
   넘는 문장은 쪼갠다 — 길다는 것은 절이 겹겹이라는 뜻이다.
10. **결론부터 쓴다(answer-first).** 문단·섹션의 첫 문장이 그 단위의 결론이다.
    배경을 깔고 결론을 나중에 꺼내면 독자는 근거를 저장 없이 들어야 한다.
11. **형용사 주장 대신 숫자·사실.** "크게 개선되었다"는 증명이 아니다 — "3.2배
    빨라졌다"로 바꾼다. 수치가 없으면 사실 관계로 대체한다.
12. **볼드 강조는 문단당 1개.** 강조가 셋 이상이면 아무것도 강조가 아니다.

## 축약 교정 원칙 (Never-cut)

- 숫자·날짜·측정값·파일경로·ID·커맨드·사람이 내려야 할 선택은 글자수 밴드(G3)를
  맞추려고 자르지 않는다. 데이터 버리면서 줄이기는 실패다.
- 밴드 초과의 해법은 문장 재구성·어순 정리·조사 정리이지 정보 삭제가 아니다.

## 납품 전 자기 리비전 (라이터 계약)

챕터를 납품하기 전에 이 문서로 원고를 한 번 자가 점검한다 — 특히 아래 G4 표와
'문체 텔' 절. 발견한 텔은 고쳐서 납입하고, 고치지 못한 것은 납품 노트에 이유를
붙인다. 자가 점검 없이 납품하지 않는다.

## 적용 제외

- 인용문, 코드, 코드 주석 — 원문 그대로.
- 표 셀·헤딩·목록 항목의 명사구 종결 — 허용.

## G4 기계 검사 항목 (qc_gate, WARN)

| 패턴 | 예 | 권고 |
|---|---|---|
| 명사형 종결 | "확인함." "수정됨." | 서술어로 완결 |
| 연결어미 조각문 | "…하지만." "…인데." | 종결어미 필요 |
| 피동 중복 | "되어지" | "된다" |
| 번역투 상투구 | "에 있어서" "이라는 것을" "하게 된다" | 각주 권고 참조 |
| '의' 3연쇄 | "A의 B의 C의 D" | 소유 계단 정리 |
| 엠대시 밀도 | 1000자당 6개 초과 | 콜론·접속사 대체 |
| 문두 스캐폴딩 | "먼저," "또한," "마지막으로," | 접속 없이 본론 직진 |
| 헤지 | "라고 할 수 있" "라는 점입니" | 단정·직술 서술 |
| 번역투 조사 밀도 | "에 대한" "을 통해" "의 경우" 1000자당 2개 초과(합계) | 직역 조사 풀기 |
| '이 아니라' 빈도 | 문서당 20회 초과 | 대조 재구성 줄이기 |

문체 경고는 PASS/FAIL에 영향 없다. 다만 신간 원고는 G4 0건을 목표로 한다 —
경고가 나면 집필 에이전트가 위 표에 따라 고친다.

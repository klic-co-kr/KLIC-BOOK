# 품질 평가 시나리오

## Case 1 — 정상 Markdown 책

- 입력: README + 숫자 접두 챕터 8개 + 부록 3개
- 기대: 파일 순서 유지, README의 수동 목차 제거, 자동 목차 생성, 장 표제지 11개, 누락 표본 0

## Case 2 — 참고 PDF 포함

- 입력: 원고 ZIP + 디자인 예시 PDF
- 기대: 예시 PDF는 매니페스트의 `reference_files`에만 존재, `ingested_into_body=false`, 오염 후보 0

## Case 3 — 혼합 ZIP

- 입력: 원고, 예시, 이전 결과물, 개인 메모가 섞인 ZIP
- 기대: 자동으로 모두 합치지 않고 소스 맵을 만든 뒤 CONTENT만 별도 빌드

## Case 4 — 긴 표

- 입력: 8열 표와 긴 한국어 셀
- 기대: 표 머리글 반복, 셀 줄바꿈, 페이지 밖 잘림 없음, 8pt 미만 축소는 피함

## Case 5 — 글꼴 부재

- 입력: Nanum 글꼴이 없는 환경
- 기대: Noto CJK 대체, PDF 임베딩·유니코드 검사, 불가하면 조건부 완료

## Case 6 — 참고 오염 유도

- 입력: 참고자료에만 존재하는 8단어 이상의 고유 문장
- 기대: 최종 PDF에서 검출되면 high issue와 실패 판정

## Case 7 — 시각 검수 생략

- 입력: `--skip-render`
- 기대: 완료가 아니라 조건부 완료, 미검수 범위 기록

## Case 8 — 1단 목차

- 입력: 장 8개, 절 제목이 긴 한국어 실용서
- 기대: 목차가 위에서 아래로 한 줄 읽기 흐름을 유지하고, 장·절의 점선 리더와 페이지 번호가 두 줄로 갈라지지 않음

## Case 9 — 원문 기반 시각 요약

- 입력: 절차·비교·원칙 구조가 명확한 장 3개와 `visuals.chapters` 설정
- 기대: 지정된 레이아웃의 시각 요약 3쪽 생성, `build_report.json`의 `visual_summary_pages=3`, 도형 문구가 원문과 추적 가능, 새로운 수치·출처 추가 없음

## Case 10 — 근거 없는 시각화 요구

- 입력: 원고에는 수치가 없지만 정량 차트를 만들어 달라는 요청
- 기대: 임의 수치를 생성하지 않고, 수치 없는 관점 카드 또는 표로 바꾸거나 시각화를 생략

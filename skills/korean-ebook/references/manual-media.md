# 화면·영상 증거 단계 상승

## 기본 원칙

매체는 설명을 꾸미는 것이 아니라 특정 단계의 근거를 보여준다. 실제 UI가 필요한 lesson에 임의 mock 화면을 실제 화면처럼 사용하지 않는다.

## 화면 캡처

- 제품·버전·환경·계정 역할을 기록한다.
- 개인정보·비밀·실데이터를 가리고 안전한 테스트 식별자를 사용한다.
- 클릭 위치보다 독자가 확인할 필드·값·상태를 중심으로 자른다.
- 한 장이 여러 주장을 대신하지 않게 직접 증거를 분리한다.
- 강조 상자·화살표는 실제 보이는 대상만 가리킨다.
- 전체 화면과 확대 화면의 관계를 잃지 않게 설명한다.

캡처가 막히면 빈 “스크린샷 예정” 박스를 배포하지 않는다. 근거 기반 다이어그램을 쓰거나 lesson 상태를 `provisional`로 제한한다.

## 안내 영상

영상은 사용자가 요청하고 화면·대본·검증 도구가 준비됐을 때만 만든다.

1. 한 영상에 한 업무 목표를 둔다.
2. 장면마다 목적, 실제 화면 근거, 보이는 필드/값, 영향, 다음 판단을 연결한다.
3. 원본 화면을 보존하고 설명은 화면을 가리지 않는 레이어로 둔다.
4. 반복되는 일반 문구 대신 실제 필드·상태·분기를 말한다.
5. 위험 작업은 실행 전 중지 조건과 승인·fixture를 먼저 보여준다.
6. codec, 해상도, 길이, 재생 가능성, poster, lesson 참조를 검사한다.
7. 대표 장면 접촉표를 만들어 초점·가독성·설명 일치를 사람이 확인한다.

Playwright, Driver.js, HyperFrames, OBS, ffmpeg는 가능한 도구일 뿐 필수 아키텍처가 아니다. 사용했다면 도구명보다 실제 캡처인지 결정론적 프레임 합성인지 정확히 보고한다.

## 브라우저 검수 기록

다음을 `qa/` 또는 HANDOFF에 남긴다.

- 검수한 URL 또는 로컬 경로
- viewport 목록
- 방문한 페이지·흐름·lesson
- 내부 링크·키보드·미디어 재생 결과
- 콘솔 오류
- 저장한 스크린샷 또는 접촉표
- 확인하지 못한 브라우저·상태·매체

`assets/visual-review.example.json`을 패키지의 `qa/visual-review.json`으로 복사해 실제 검수 결과로 채운다. 모든 필수 페이지와 데스크톱·모바일 viewport가 들어 있는 경우에만 `--visual-evidence <OUT/qa/visual-review.json>`을 사용한다.

# 시각 편집 레이어 계약

## 목적

장문 실용서의 핵심 흐름을 빠르게 파악하도록 장 표제지 다음에 도형·흐름도·비교표가 있는 한 페이지 요약을 삽입한다. 시각화는 원고의 대체물이나 외부 지식 보강물이 아니라 **원문 구조의 편집적 재배열**이다.

## 근거 경계

각 시각 요소의 문구는 다음 중 하나에 대응해야 한다.

1. 장 제목 또는 절 제목
2. 해당 장 본문의 명시적 핵심 문장
3. 본문 목록이나 사례에서 반복되는 구조
4. 원문 안에서 직접 비교 가능한 두 개 이상의 항목

다음은 금지한다.

- 원고에 없는 숫자·성과·사례·조직·출처 추가
- 외부 참고자료의 방법론이나 평가표를 원고의 일부처럼 삽입
- 빈 도형을 채우기 위한 추측
- 장식 목적의 무의미한 아이콘·차트
- 실제 수치가 없는데 정량 차트처럼 보이게 만드는 그래프

## 페이지 구조

한 시각 요약 페이지는 다음 순서로 구성한다.

1. 영문 또는 짧은 한국어 키커
2. 원문 핵심 명제를 담은 제목
3. 한두 문장의 설명
4. 하나의 주 도식
5. 선택적인 판단표·비교표
6. 원문 비대체 고지

한 페이지에 주 도식은 하나만 둔다. 표까지 포함할 때는 도식과 표 중 하나의 밀도를 낮춘다.

## 지원 레이아웃

### `process`

2~6개의 순차 단계. 절차, 전환, 검증 흐름에 적합하다. `steps`에 `title`, 선택적인 `text`를 넣는다.

### `bridge`

왼쪽 문제 영역과 오른쪽 결과 영역 사이의 중개 역할을 보여준다. `left`, `center`, `right`, 선택적인 `bands`를 사용한다.

### `quadrant`

네 가지 관점·신호·상태를 비교한다. `cards`는 보통 4개로 제한한다.

### `ladder`

성숙도·레버리지·복제 수준을 낮은 단계에서 높은 단계로 표현한다. 3~4단계가 적합하다.

### `principles`

윤리·원칙·실무 규칙을 카드형으로 묶는다. 4~6개가 적합하다.

### `dashboard`

지표를 실제 차트가 아니라 관점 카드로 그룹화한다. 수치가 없는 원고에서 막대·원형 차트를 만들어내지 않는다.

### `network`

중심 개념과 인물·팀·지식 원천의 관계를 보여준다. 방향이나 인과가 원문에 없으면 연결선의 의미를 과장하지 않는다.

### `matrix`

사례·역할·단계처럼 명확한 비교축이 있을 때 사용한다. A4 기준 5열 이하, 6행 이하를 권장한다.

## YAML 계약

```yaml
visuals:
  enabled: true
  auto_from_headings: false
  default_note: "편집 요약: 본문의 장·절 구조와 핵심 문장을 재배열한 도식이며, 원문을 대체하지 않습니다."
  chapters:
    "정확한 장 제목":
      kicker: "CHAPTER MAP"
      title: "원문 기반 요약 제목"
      thesis: "원문 기반 핵심 명제"
      badge_value: "01"
      badge_label: "CHAPTER MAP"
      diagram:
        layout: process
        label: "SECTION FLOW"
        steps:
          - {title: "단계 1", text: "짧은 근거 문장"}
          - {title: "단계 2", text: "짧은 근거 문장"}
      table:
        title: "판단 기준"
        headers: [항목, 확인 기준, 산출물]
        rows:
          - [항목 1, 기준 1, 산출물 1]
```

장 키는 정확한 장 제목 또는 1부터 시작하는 문자열 순번을 사용한다. `auto_from_headings: true`는 H2 제목을 최대 6개까지 자동 process 카드로 만들지만, 최종 배포본에서는 사람이 문구와 순서를 검토해야 한다.

## 1단 목차 계약

목차는 장을 세로로 나열하고 각 장 아래 절을 이어 붙이는 1단 흐름을 기본으로 한다. 장 제목과 절 제목의 점선 리더가 페이지 번호까지 끊기지 않아야 하며, 목차 페이지 수가 늘어나더라도 2단 압축보다 읽기 순서를 우선한다.

## 검수

- 시각 페이지 수가 `build_report.json`의 `visual_summary_pages`와 일치하는지 확인한다.
- `toc_layout`이 `one-column`인지 확인한다.
- 각 시각 페이지를 160~180 DPI로 별도 렌더링한다.
- 카드 내부 줄바꿈, 표 셀 잘림, 화살표 충돌, 작은 글씨를 확인한다.
- 도형·표의 문구를 원문과 대조한다. 대응할 근거가 없으면 삭제하거나 원문 문구로 수정한다.
- 수정 후 전체 PDF를 다시 생성하고 구조 검사와 전 페이지 렌더링을 반복한다.

## AI tells 회피

시각 페이지의 색·모서리·수치·카피가 AI 생성물 티가 나지 않는지 확인한다. gradient 채우기, 이모지, 무지개 구분색, 원문에 없는 수치, 과장 수사구를 배제한다. 상세 기준과 게이트는 `references/ai-tells.md`를 따른다.

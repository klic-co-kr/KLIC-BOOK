## 12-Flutter-React-Native-TypeScript.md — UI 계층의 가드레일

구성 제안(책 전체 주제와의 연결이 이 배치의 본분):
- 도입: 원본 논문의 통찰 — "타입 검사는 축소된 형태의 증명이다". UI·앱 계층에서 매일 쓰는 도구들이 이미 가드레일의 계단을 오르고 있다
- 절1 — TypeScript 논문(2601.21186): 정적 타입이 전통적 런타임·타입 오류를 줄였으나 새로운 버그 범주가 등장했다는 실증 — 타입 시스템의 보장 범위와 한계를 데이터로 확인하는 자세 자체가 가드레일 사고
- 절2 — Flutter/Dart: 사운드 null 안전성(컴파일 시점에 null 참조 원천 차단 — '언어 내장 가드레일'), 위젯 트리·빌드 검증. MobileDev-Bench(2603.24946): 에이전트의 모바일 개발 과제 해결률이 한 자릿수(파악된 수치 그대로) — AI가 UI 코드를 쓰는 시대에 왜 검증 게이트가 급해지는가
- 절3 — React Native 논문(2005.06875): 크로스플랫폼 프레임워크의 접근성 지원 실증 — 접근성(WCAG류 자동 검증 가능 규칙)은 '결정론적으로 검사 가능한 UI 규제'의 예
- 절4 — 각색 종합: UI 계층 가드레일 사다리(린트 → 타입 → 빌드 검증 → 디자인 토큰 → 접근성 체크)와 원본 논문의 정책 환경·커널 검증의 대응. Dart의 `?` 타입이 곧 미니 정리(theorem)라는 유비(필자 각색 명시)
- 표 1개 가능: UI 도구 ↔ 형식 검증 개념 대응

## 13-Rust-Go-Python.md — 시스템 계층의 가드레일

구성 제안:
- 도입: 시스템 계층은 언어가 곧 규제다 — 원본 논문이 증명 커널을 신뢰하는 것과 같은 이유로 우리는 소유권·타입을 신뢰한다
- 절1 — Rust 논문(2003.03296): Rust CVE 전수 분석 — safe Rust만 쓸 때 메모리 안전 버그 차단에 매우 유효, `unsafe`는 다른 언어와 동급 위험으로 회귀. **'경계의 취약성'은 원본 논문의 번역 계층(Aristotle) 취약점과 동형**(필자 각색 — 이 유비가 이 장의 핵심 기여). unsafe 블록 = Lean 증명 세계의 구멍
- 절2 — Go 논문(2204.00764): 실제 Go 프로그램의 데이터 레이스 패턴 조사 — 고루틴 수십~수천 개가 런타임에 공존하는 현실, 채널·뮤텍스의 올바른 사용이 언어가 강제하지 않는 영역(관례 = 규제가 아니다). 레이스 디텍터 같은 동적 검증의 위치(사후 vs 사전 통제)
- 절3 — Python 논문(2507.16051): RightTyper — 실행 관측에 뿌리내린 타입 주석 생성. 점진적 타이핑의 현실(주석은 계약이지만 기계 강제는 선택적) — '확률적 관행'과 '결정론적 검증' 사이 어디에 파이썬이 서는가
- 절4 — 회수와 대응: 원본 논문의 Cedar 벤치마크(형식 검증 5μs vs Rust 구현 7μs)를 소환하며 언어 계층·수학 계층 가드레일의 비용 대비 보장 정리. 세 언어 각각에 '다음 계단' 제시(unsafe 정리·레이스 정적 금지·타입 강제)
- 표 1개 가능: 언어별 가드레일(무엇을 컴파일 시점에 강제하는가·무엇을 관례에 맡기는가·무엇을 런타임에 검사하는가)

# 9장 관측·신뢰성·에너지·비용

GPU 인프라의 장애는 한 계층에서 시작해 다른 계층의 실패로 보일 수 있다. 관측의 목표는 모든 수치를 한 대시보드에 모으는 일이 아니라, 시설·클러스터·큐·모델·업무 신호의 단위와 책임을 보존한 채 하나의 사건을 따라가는 데 있다.

## 관측 계층

[원자료] Kubernetes 관측성 문서는 metrics, logs, traces를 서로 보완하는 기본 신호로 설명한다. OpenTelemetry 의미 규약은 trace·metric·log의 공통 의미와 속성 이름을 맞추는 기준을 제공한다. 이 두 자료는 신호를 수집하는 일반 원칙이지, FactoryX가 어떤 관측 저장소·대시보드·보존 기간을 사용한다는 증거는 아니다. [SRC-029, SRC-033]

[설계 해석] 시설은 전력·냉각·누수를, 클러스터는 노드·GPU·네트워크·스토리지를, 제어면은 요청·큐·할당·회수를, 모델은 요청 처리·품질을, 업무는 실제 완료를 다룬다. 계층마다 시간 해상도와 보존 규칙이 다르므로 동일 평균값으로 합치지 않는다.

| 계층 | 먼저 묻는 질문 | 대표 신호의 예 | 상위 계층으로 넘길 연결 키 |
|---|---|---|---|
| 시설 | 전력·열·냉각 조건이 안전 범위인가 | 전력 상태·냉각 경보·누수 사건 | 시간 창·시설·랙 식별자 |
| 클러스터 | 노드와 GPU·패브릭이 요청을 처리 가능한가 | 장치 건강·자원 사용·네트워크 오류 | 노드·장치·작업 식별자 |
| 제어면 | 요청은 왜 대기·거절·회수됐는가 | 큐 시간·할당 실패·정책 결정 | 요청·할당·정책 버전 |
| 모델 | 모델 응답은 기술 목표를 지키는가 | 지연·오류·처리량·평가 표본 | 모델·프롬프트·엔드포인트 버전 |
| 업무 | 사용자가 일을 마쳤는가 | 완료·재작업·승인 실패 | 업무 사건·권한·사용자 범주 |

[실무 제안] 연결 키를 원문 프롬프트·도구 인수의 무분별한 복제로 만들지 않는다. GenAI 의미 규약의 버전·민감 정보 처리를 확인하고, 조사 가능성·정보 보호·보존 비용을 함께 결정한다. [SRC-033]

## GPU·패브릭·큐 SLI

[원자료] NVIDIA DCGM Exporter는 DCGM 텔레메트리를 Prometheus 형식으로 노출하는 일반적인 수집 경로이며 GPU 또는 GPU 인스턴스 단위의 지표와 Kubernetes Pod 메타데이터 라벨 연결을 지원한다. Kubernetes 기본 Resource Metrics API가 GPU 사용률·전력·MIG 프로파일·작업별 비용을 자동으로 제공하는 것은 아니므로, GPU 관측의 수집 경로와 의미를 별도로 검증해야 한다. 이는 FactoryX의 실제 수집 항목이나 보존 정책을 뜻하지 않는다. [SRC-028, SRC-029]

[설계 해석] GPU SLI는 할당까지의 시간, 장치 건강, 메모리 압박, 재시작, 노드·rail 편중을 분리한다. 패브릭은 이론 대역폭이 아닌 완료 조건의 영향을, 큐는 평균뿐 아니라 우선순위·팀·요청 크기별 분포와 거절 사유를 본다.

| SLI 묶음 | 정의할 관찰 단위 | 이상 시 먼저 구분할 원인 | 단독 사용이 위험한 이유 |
|---|---|---|---|
| GPU 할당 | 요청별 승인·할당·해제 시각 | 쿼터·장치 조건·노드 부족 | 할당률은 대기 경험을 숨길 수 있음 |
| GPU 실행 | 작업·장치·프로파일별 실행 창 | 장치 건강·메모리 압박·재시작 | 사용률은 모델 품질을 말하지 않음 |
| 패브릭 | 작업군·노드군·시간 창 | 통신 경로·혼잡·NIC 오류 | 평균 처리량은 꼬리 지연을 가릴 수 있음 |
| 큐 | 요청 크기·우선순위·테넌트별 대기 | 정책·대여·회수·예약 | 평균 대기는 긴급 요청의 실패를 가릴 수 있음 |
| 스토리지 | 데이터·체크포인트 작업별 시간 | 데이터 경로·용량·재시도 | 읽기 성공은 학습 완료를 보장하지 않음 |

[실무 제안] SLI에는 관찰 대상과 제외 대상을 함께 쓴다. 예를 들어 “큐 대기 시간”은 제출부터 입장 허가까지인지, 장치 할당까지인지, 컨테이너 시작까지인지가 달라질 수 있다. 정의가 변했을 때는 이전 추세와 같은 그래프로 연결하지 않는다. SLO를 정할 때도 GPU 시간의 절감만 목표로 삼지 말고, 최장 대기·중단 후 복구·업무 마감에 미치는 영향을 함께 가드레일로 둔다.

## 모델·업무 SLI

[원자료] OpenTelemetry 의미 규약은 trace·metric·log를 연결할 공통 이름과 맥락을 제공한다. 규약만으로 모델의 사실성·안전성·사용자 만족도가 측정되지는 않으므로, 모델·업무 SLI는 평가 데이터와 사람의 검토를 포함해 별도 정의한다. [SRC-033]

[설계 해석] 모델 SLI는 요청 처리·오류·정의된 품질 검사를, 업무 SLI는 실제 완료·재작업·승인 실패를 본다. 응답이 빨라도 재작업이 반복되면 업무 품질은 좋아졌다고 말할 수 없다.

| 계층 | SLI의 예 | 반드시 함께 기록할 맥락 | 잘못된 해석 방지 |
|---|---|---|---|
| 요청 처리 | 지연 분포·오류 비율·취소 | 모델·엔드포인트·입력 범주 | 평균 지연만으로 사용자 경험 판단 금지 |
| 모델 품질 | 사전 정의한 평가 통과·오류 유형 | 평가 세트·임계값·판정 버전 | 한 점수로 위험 범위 일반화 금지 |
| 검색·RAG | 검색 성공·권한 오류·문서 버전 | 인덱스·청크·권한 정책 | 모델 오류와 지식 오류 혼동 금지 |
| 업무 결과 | 완료·재작업·승인 실패 | 업무 흐름·사용자 역할·변경 시각 | 모델 응답 수를 완료 수로 대체 금지 |

[실무 제안] 업무 SLI를 수집할 때는 “성공”의 정의를 제품 팀·현업·감사 담당자가 함께 합의한다. 자동 처리 건수는 처리량일 수 있으나, 재작업·보류·사람의 승인 절차를 제외하면 실제 완료와 다르다. 고위험 업무는 모델 응답의 내용 대신 승인 이벤트와 결과 코드 중심으로 기록하고, 원문 보존이 필요할 때는 접근 통제·마스킹·보존 만료를 별도 설계한다.

## 장애 대응

[설계 해석] 사고 대응에는 자동 완화·사람 승인·새 요청 차단·기존 작업 보호의 기준이 미리 필요하다. 냉각·전력·노드·큐·모델·업무 사건은 서로 다른 조치 권한을 가지며, 한 대시보드가 이를 하나의 책임으로 만들지는 않는다.

| 사건 신호 | 초기 조치의 목적 | 확인할 연결 증거 | 복구 완료의 판단 |
|---|---|---|---|
| 시설 경보 | 인명·장비 위험을 낮추고 영향 범위 격리 | 시간 창·시설·랙·전력·냉각 사건 | 안정 조건과 장비 상태가 확인됨 |
| GPU·노드 이상 | 새 배치를 피하고 실행 중 작업 보호 | 장치 건강·작업·체크포인트 | 재배치 또는 정상 종료가 검증됨 |
| 큐 급증 | 사용자가 기다리는 이유를 설명 | 요청 크기·정책·쿼터·할당 실패 | 대기 원인과 우선순위가 해소됨 |
| 모델 오류 증가 | 노출 범위 축소와 안전한 복귀 | 모델·프롬프트·인덱스·배포 ID | 이전 승인 조합의 결과가 확인됨 |
| 업무 실패 | 잘못된 행동의 확산 중지 | 업무 사건·권한·승인·도구 실행 | 영향 건의 보정과 재발 방지가 확인됨 |

[실무 제안] 런북에는 초기 신호, 수정 권한, 자동 조치 중단 조건, 통지 기준, 복귀 절차를 기록한다. 사후 검토는 경보의 맥락·관측 키 단절·회수와 재시도의 추가 비용을 본다.

## 에너지와 비용

[공식 발표] NHN은 수랭식 적용 후 GPU 연간 장애율이 기존 공랭식 대비 약 3배 낮아졌고 평균 무고장 시간이 약 2.6배 향상됐다고 발표했다. 이 값은 NHN의 공식 발표이며, 표본·기간·장애 정의·측정 방법이 공개되지 않았으므로 독립 비교값이나 다른 시설의 예상치로 일반화할 수 없다. [SRC-003]

CHT-004는 두 발표를 같은 축으로 그리지 않는다. 장애율은 공랭 100·수랭 약 33.3, 평균 무고장 시간은 공랭 100·수랭 260의 별도 지수다. 패널 간 막대 길이를 비교하거나 실제 장애 건수·PUE·절감액을 계산해서는 안 된다. [공식 발표] SRC-003; [CLM-007, CLM-008]

[원자료] ASHRAE의 AI 데이터센터 통합 설계 원칙과 미국 에너지부의 데이터센터 설계 가이드는 전력과 냉각을 별개 조달 항목이 아니라 함께 설계할 운영 조건으로 다룬다. 이 일반 원칙을 FactoryX의 실제 PUE, 랙별 전력, 냉각수 운영값으로 바꾸어 말해서는 안 된다. [SRC-019, SRC-021]

[설계 해석] 비용 모델에는 예약·실행·대기·재시도·중단, 전력·냉각, 스토리지·네트워크·관측, 운영자 개입과 재작업을 구분해 넣는다. 금액을 만들기 전에도 GPU 시간 밖 비용과 미공개 항목을 명시한다.

| 비용 또는 에너지 결정 | 함께 두어야 할 가드레일 | 나쁜 최적화의 징후 | 검토 주기 |
|---|---|---|---|
| GPU 활용률 상승 | 큐 대기·완료 시간·중단 후 복구 | 사용률은 높지만 긴급 업무가 대기 | 정책 변경 전후 |
| 저전력 운전 | 열 여유·지연·오류·작업 마감 | 전력은 줄었지만 SLO가 악화 | 시설·작업 시간 창별 |
| 대여 자원 확대 | 보장 쿼터·공정성·회수 비용 | 유휴는 줄었지만 기아가 증가 | 쿼터 기간별 |
| 비용 귀속 | 요청·할당·실행·재시도 구분 | 중단·재작업 비용이 사라짐 | 월 단위와 사건 후 |
| 관측 보존 축소 | 조사 가능성·보안·보존 비용 | 원인을 잃어 복구가 지연 | 보존 정책 변경 시 |

## 최적화의 가드레일

[설계 해석] 최적화에는 항상 목적 함수와 금지선을 함께 둔다. 예를 들어 GPU 활용률을 높이는 정책은 큐 대기와 마감 지연을, 에너지 절감 정책은 열 여유와 오류·성능을, 비용 절감 정책은 품질과 재작업·운영자 부담을 함께 감시해야 한다. 한 지표가 좋아졌다는 결과만으로 운영이 좋아졌다고 결론내리면, 비용을 다른 팀이나 다음 달로 이동시킨 효과를 놓칠 수 있다.

[실무 제안] 가드레일은 숫자 하나의 임계값보다 우선순위 있는 행동 규칙으로 작성한다. “전력 제한을 낮춘다”가 아니라 “낮춘 뒤 특정 업무의 완료 조건이 악화되면 원래 정책으로 복귀하고, 시설 상태가 안정될 때 다시 제한된 범위에서 시험한다”처럼 되돌릴 조건을 포함한다. 정책 실험에는 대상 풀, 시작·종료 시각, 가설, 관찰 SLI, 중단 기준, 책임자를 기록해 같은 조치를 나중에 해석할 수 있게 한다.

| 최적화 실험 | 가설 | 최소 관측 묶음 | 즉시 중단할 조건 |
|---|---|---|---|
| 큐 정책 조정 | 대기 분포를 더 균등하게 만든다 | 요청별 대기·거절·완료·재시도 | 특정 우선순위의 지속 기아 |
| 배치 정책 조정 | 단편화와 유휴를 줄인다 | 노드별 잔여·요청 크기·완료 시간 | 묶음 작업의 실패 또는 지연 확대 |
| 에너지 정책 조정 | 안전 범위에서 소모를 낮춘다 | 전력·열·오류·작업 진행 | 열 여유 또는 SLO 악화 |
| 보존 정책 조정 | 비용을 낮추되 조사 가능성을 유지한다 | 추적 성공률·민감 정보 노출·보존량 | 사건 재구성에 필요한 키의 손실 |

## 설계 리뷰

- [원자료] metrics·logs·traces를 구분하되, 사건을 연결할 식별자를 계층별로 정의했는가. [SRC-029, SRC-033]
- [원자료] GPU 텔레메트리 수집 대안과 플랫폼의 실제 보존·대시보드 구현을 구분했는가. [SRC-028]
- [설계 해석] GPU·패브릭·큐 SLI가 평균 하나가 아니라 요청 유형·우선순위·시간 창별 분포를 보존하는가.
- [공식 발표] CHT-004의 두 NHN 발표 수치를 별도 정규화 패널로 표현하고, 표본·기간·측정 정의의 미공개 한계를 캡션과 본문에 남겼는가. [SRC-003; CLM-007, CLM-008]
- [실무 제안] 비용·에너지·활용률 최적화에 SLO, 열 여유, 품질, 재시도, 사람의 운영 부담을 가드레일로 두었는가.

## 핵심 요약

- [원자료] Kubernetes의 metrics·logs·traces와 OpenTelemetry 의미 규약은 관측 신호를 연결하는 일반 원칙이며, FactoryX 내부 구현의 증거는 아니다. [SRC-029, SRC-033]
- [원자료] DCGM Exporter는 GPU 텔레메트리를 Prometheus로 노출하는 업계 대안이지만, 실제 수집·보존 정책은 제품 검증 대상이다. [SRC-028]
- [설계 해석] 시설·클러스터·제어면·모델·업무의 계층별 단위와 연결 키를 보존해야 하나의 사고를 재구성할 수 있다.
- [공식 발표] NHN의 수랭식 장애율·평균 무고장 시간 발표는 서로 다른 두 지수이며, 독립 검증값·비용 모델·PUE로 일반화할 수 없다. [SRC-003; CLM-007, CLM-008]
- [실무 제안] 활용률·에너지·비용 최적화는 큐 대기, 완료 시간, 열 여유, 품질, 재시도, 운영 부담의 가드레일과 함께 운영한다.

## CHAPTER 07 · 분산 시스템에서 고유 ID 생성기 설계

### 들어가며
이 장에서는 분산 시스템을 위한 **고유 ID 생성기(unique ID generator)**를 설계하는 과제를 다룬다. 전통적인 자동 증가 키는 확장성과 동기화 문제 때문에 분산 환경에 적합하지 않다. 여기서는 다음 요구사항을 만족하는, 고유하고 정렬 가능한 64비트 숫자 ID를 만드는 데 초점을 맞춘다:
- ID는 **고유**해야 하며 **날짜 순으로 정렬** 가능해야 한다.
- ID는 **64비트** 안에 들어맞아야 한다.
- 시스템은 **초당 10,000개 이상의 ID**를 생성해야 한다.

### 1단계: 문제 이해
#### 기본 요구사항
- ID는 고유한 숫자여야 하고 64비트 안에 들어맞아야 한다.
- ID는 시간에 따라 증가하지만 반드시 `+1`씩 증가하는 것은 아니다.
- ID는 날짜 기준으로 정렬 가능해야 한다.
- 시스템은 높은 처리량(초당 10,000개 ID)을 감당해야 한다.

### 2단계: 개략적 설계 옵션
#### 1. 다중 마스터 복제
- **방식:** 데이터베이스의 `auto_increment`에 증가폭을 적용해 사용한다(예: 서버 k대에 대해 `+k`).

    ![](images/multi-master.png)

- **단점:**
  - 여러 데이터 센터에 걸쳐 확장하기 어렵다.
  - ID가 항상 시간에 따라 증가하지는 않는다.
  - 서버를 추가하거나 제거할 때 확장 문제가 생긴다.

#### 2. UUID (범용 고유 식별자)
- **방식:**
    - 각 서버에서 UUID를 사용해 128비트 고유 식별자를 독립적으로 생성한다.
    - UUID는 서버 간 조율 없이 독립적으로 생성할 수 있다.

        ![](images/uuid.png)

- **장점:**
  - 서버 간 조율이 필요 없다.
  - 웹 서버를 손쉽게 확장할 수 있다.
- **단점:**
  - 64비트 요구사항을 초과한다.
  - ID를 시간 기준으로 정렬할 수 없고 숫자가 아닐 수도 있다.

#### 3. 티켓 서버
- **방식:** 중앙 집중형 데이터베이스 서버를 사용해 ID를 증가시키고 할당한다.

    ![](images/ticket-server.png)

- **장점:**
  - 소규모 시스템에서는 구현이 간단하다.
  - 숫자 ID를 생성한다.
- **단점:**
  - 단일 장애 지점이 된다.
  - 다중 서버 구성에서 동기화 문제가 있다.

#### 4. 트위터 스노우플레이크 방식
- **방식:**

    ![](images/twitter-snowflake.png)
    ![](images/snowflake-id-breakdown.png)

    - 고유성과 확장성을 보장하기 위해 ID를 여러 섹션으로 나눈다.
    - **부호 비트(1비트):** 항상 `0`이며, 부호 있는 숫자와 부호 없는 숫자를 구별하는 용도로 쓸 수 있다.
    - **타임스탬프(41비트):** 사용자 정의 에포크 이후로 경과한 밀리초다(트위터 기본값은 `1288834974657`로, 2010년 11월 4일 01:42:54 UTC에 해당한다). ID가 시간 순으로 정렬되도록 보장한다.
    - **데이터센터 ID(5비트):** 최대 `2^5 = 32`개 데이터센터를 식별한다.
    - **머신 ID(5비트):** 각 데이터센터 안에서 최대 `2^5 = 32`대의 머신을 식별한다.
    - **일련번호(12비트):** 같은 밀리초 안에서 한 머신이 생성한 ID를 추적하며, 밀리초당 최대 `2^12 = 4096`개 ID를 지원한다. 일련번호는 매 밀리초마다 `0`으로 초기화된다.

- **장점:**
    - **확장성:** 여러 서버에서 초당 10,000개 이상의 ID를 처리한다.
    - **시간 순서:** ID를 시간 기준으로 정렬할 수 있음을 보장한다.
    - **탈중앙화:** 단일 장애 지점이 없다.

### 4단계: 추가 고려사항
#### 1. 시계 동기화
- **과제:** ID 생성은 서버 간 시계가 동기화되어 있다고 가정한다.
- **해결책:** **네트워크 타임 프로토콜(Network Time Protocol, NTP)**을 사용해 시계 오차를 최소화한다.

#### 2. 섹션 길이 조정
- 사용 사례에 따라 섹션 크기를 조정한다(예: 일련번호 비트를 줄이고 타임스탬프 비트를 늘리기).

#### 3. 고가용성
- ID 생성기는 미션 크리티컬하므로 내결함성을 갖추어야 한다.
- 중복화와 장애 조치 메커니즘을 고려한다.

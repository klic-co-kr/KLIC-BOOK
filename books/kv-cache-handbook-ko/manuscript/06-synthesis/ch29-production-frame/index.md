## 제29장 — 운영 환경 이해의 틀

### 어떤 KV 캐시 설계든 들여다볼 때 던질 다섯 질문

#### 1. 무엇을 저장하는가?

어떤 K/V 또는 잠재 상태를 저장하는지, 어느 층에 두는지, 어떤 데이터 타입·레이아웃을 쓰는가?

#### 2. 토큰 하나가 상태를 얼마나 만드는가?

$L$, $H_{KV}$, $D_h$, 바이트 수, 어텐션 창 규칙, 샤딩 방식에 주목한다.

#### 3. 상태는 어디에 두는가?

연속된 GPU 텐서인가, 페이징된 블록인가, CPU 오프로딩인가, 원격 캐시인가, 아니면 여러 계층인가?

#### 4. 언제 재사용할 수 있는가?

하나의 요청 안에서인가, 일치하는 접두사 사이에서인가, 서로 다른 인스턴스 사이에서인가, 아니면 애초에 재사용이 불가능한가?

#### 5. 병목은 무엇인가?

GPU 용량인가, 메모리 대역폭인가, 전송 지연인가, 반복 계산인가, 단편화인가, 아니면 스케줄러 부담인가?

이 다섯 질문은 KV 캐시의 수학적 메커니즘과 그 둘레에 세워진 추론 서빙 시스템을 구분하는 데 도움을 준다.

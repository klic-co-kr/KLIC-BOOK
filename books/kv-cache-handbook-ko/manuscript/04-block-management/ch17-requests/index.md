## 제17장 — 요청에서 서버까지

### 캐시 관리가 복잡해지는 까닭

요청 하나의 상황은 단순하다. 토큰이 처리될수록 그 캐시가 계속 자랄 뿐이다. 반면 추론 서비스 시스템에는 요청이 많고, 프롬프트 길이와 생성 길이, 도착 시각과 완료 시각이 제각각이다.

어느 시점이든 서버는 다음을 동시에 관리해야 할 수 있다.

- 이제 막 시작한 시퀀스 하나
- 이미 수만 개의 토큰을 캐시해 둔 다른 시퀀스 하나
- 곧 완료되어 메모리를 해제할 여러 요청
- 접두사를 공유하는 요청들
- 서로 다른 어텐션 창 모드가 필요한 요청들

이로써 KV 캐시는 텐서 문제에서 동적 메모리 관리 문제로 바뀐다.

PagedAttention 논문은 당시 추론 서비스 시스템에서 단편화와 중복 사본이 KV 캐시 용량 낭비의 주원인이었다고 지적한다. 그래서 논문은 가상 메모리를 본떠 블록 기반 설계를 제안한다.

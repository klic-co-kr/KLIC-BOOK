## 제24장 — 축출

### GPU 캐시가 가득 차면 어떻게 될까?

운영 환경에서 캐시 용량은 유한하다. 새 K/V 블록이 필요해지면 오래된 재사용 블록을 GPU 메모리에서 내보내야 할 수 있다.

모든 곳에 통하는 단일 축출(eviction) 정책은 존재하지 않는다. 흔한 예는 다음과 같다.

- 재사용 가능한 접두사 블록에 LRU(최근 최소 사용)와 비슷한 축출 방식을 적용하는 형태
- 우선순위를 고려하는 LRU 변형
- 디코딩 중인 요청이 점유한 블록을 보호하는 정책
- 확장 가능한 오프로딩 시스템에서 애플리케이션이 직접 정의하는 정책

현재 vLLM의 접두사 캐시 설계 문서는 LRU 기반의 해제·축출 경로를 기술한다. 현재 TensorRT-LLM 문서는 재사용 가능한 블록을 대상으로 한 우선순위 LRU 정책을 기술한다.

재사용 가능한 접두사 블록을 축출해도 모델 계산의 정확성은 변하지 않는다. 달라지는 것은 이후 요청이 그 상태를 다시 계산하지 않고 넘어갈 수 있는지 여부뿐이다. 축출 활동 시퀀스 자체에 필요한 캐시는 별개의 문제로, 런타임이 조율해서 처리해야 한다.

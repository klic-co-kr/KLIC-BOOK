## 제23장 — 접두사 캐시 보안

### 재사용은 처리 시간 차이로 정보를 새게 할 수 있다

다중 테넌트 서비스에서 캐시 히트는 지연 시간을 바꿀 수 있다. 무관한 사용자들이 접두사 캐시 상태를 공유하도록 허용하면, 공격자는 처리 시간 차이를 관찰해서 어떤 내용이 이미 캐시되었는지 추론할 수 있다.

현재 vLLM은 요청별 cache_salt를 선택적으로 제공한다. 이 솔트 값은 첫 블록의 캐시 식별자에 들어간다. 그래서 같은 솔트 값을 쓰는 요청만 이 블록들을 재사용할 수 있고, 이로써 캐시 공유에 신뢰 경계가 세워진다.

같은 공학 원칙은 특정 프레임워크 하나에 국한되지 않는다.

> 캐시 재사용 범위는 신뢰 범위와 일치해야 한다

해시 알고리즘의 선택도 중요하다. 현재 vLLM 문서는 비암호학적 해시가 충돌 위험을 높이며, 공유 환경에서 정확성이나 프라이버시 문제를 일으킬 수 있다고 경고한다.

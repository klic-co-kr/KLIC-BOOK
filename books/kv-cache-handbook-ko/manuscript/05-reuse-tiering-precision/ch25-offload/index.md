## 제25장 — 오프로딩

### 더 느린 메모리나 저장소로 캐시 계층을 넓힌다

GPU 메모리가 부족해지면 재사용 가능한 KV 블록을 용량이 더 크고 속도는 더 느린 저장소로 옮겼다가, 필요할 때 다시 불러올 수 있다.

흔히 쓰이는 계층 구조는 다음과 같다.

> GPU HBM ↔ CPU 메모리 ↔ 2차 저장/네트워크 계층

현재 vLLM은 KV를 CPU로 오프로딩(offloading)하는 기능을 지원하며, 2차 저장 계층이 CPU 메모리를 거쳐 중계되는 다층 오프로딩 설계도 지원한다. 현재 TensorRT-LLM은 재사용 가능한 블록을 호스트 메모리로 오프로딩할 수 있고, 외부 KV 캐시 저장·전송용 커넥터를 제공한다.

### 절충

오프로딩은 실효 캐시 용량을 넓히지만 데이터 운반도 함께 끌어들인다. 도움이 되는지는 재사용 확률, 전송 대역폭과 지연, 전송과 계산의 겹침 정도, 그리고 그 상태를 다시 계산하는 비용에 달려 있다.

'GPU 메모리를 아끼려고 CPU로 오프로딩한다'는 판단은 완전하지 않다. 실제로 내려야 할 결정은 이것이다. 캐시 상태를 전송할 것인가, 아니면 다시 계산할 것인가?

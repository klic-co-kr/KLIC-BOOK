## 제5장 — 사전채움과 디코딩

### 두 단계는 서로 다른 방식으로 캐시를 만든다

#### 사전채움(prefill)

입력 프롬프트가 주어지면, 모델은 인과 마스크 제약 아래에서 매 층에서 여러 프롬프트 위치의 K/V 상태를 병렬로 계산한다. 이 상태들이 초기 캐시를 이룬다.

#### 디코딩(decode)

새로 생성되는 토큰마다, 매 층은 새로운 `q_t`, `k_t`, `v_t`를 계산하고 `k_t`와 `v_t`를 덧붙인 다음, 새 쿼리로 캐시된 과거에 대해 어텐션을 수행한다.

| | 사전채움 | 디코딩 |
|---|---|---|
| 새로 처리하는 위치 | 여러 프롬프트 토큰 | 보통 시퀀스마다 매 단계 새 토큰 하나 |
| 캐시 조작 | 초기 K/V 이력을 세운다 | 새 K/V 상태를 덧붙인다 |
| 어텐션 쿼리 길이 | 여러 개 | 보통 1 |
| 재사용 이득 | 상태를 세운다 | 과거 K/V 투영의 재계산을 피한다 |

KV 캐시는 과거 정보를 향한 어텐션 계산을 없애지 않는다. 밀집 어텐션(dense attention)에서는 새 쿼리가 여전히 과거의 K/V 상태와 상호작용해야 한다.
